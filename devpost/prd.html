00

Decisions made at review

Group precedence

Any clear failure → Not eligible, review notes still listed. Else any flag → Needs review. Else Eligible.

Near-limit example

74.6 is within 1 of 75 → review. Clear failures use values outside the margin (72).

Duplicate names

Initials match in position (s kumar ↔ suresh kumar) plus "Also match duplicates on" columns. Both rows flagged, each naming the other.

01

The Core Journey

Develops scope.md › The Core Loop, What "Working" Looks Like

  1. Open Rollcheck: name, one line, drop zone, "Try sample data", privacy line.
  2. Drop or pick a .csv / .xlsx, or try sample data.
  3. Rules screen: summary, sheet picker, ID and name columns, typed 5-row preview.
  4. Add 1–5 rules, adjust margin, or load a rule set. Check students.
  5. Results: "N of N students checked", counters, impact, table with Needs review first.
  6. Filter, search, open a row for every cell and reason.
  7. Download .xlsx. Success: every row with Status and Reason, counts add up.
  8. Next cycle: new export, load the saved rule set.

Reading the File

  • CSV delimiter auto-detected (comma, semicolon, tab).
  • First non-empty row is the header.
  • Duplicate / blank headers renamed ("Column 7"), user told.
  • Cells shown exactly as in the file: "00417" stays "00417".
  • 50,000+ rows: page stays responsive, progress text.
States and errors5
  • Reading: progress text, drop zone disabled.
  • Wrong type: Only .csv and .xlsx files are supported.
  • Empty / headers only: This file has no student rows.
  • Unreadable: This file could not be read. Check that it opens in Excel, then try again.
  • First use: nothing remembered except the theme.
How we'll know it works3
  • student-mat.csv (semicolon) shows correct row and column counts and preview.
  • Three blank rows above the header: fourth row used as headers.

Building Rules

  • 1–5 rules, AND. "Add rule" disabled at 5.
  • "Also match duplicates on" column picker, pre-filled from headers.
  • is at least · is at most · equals · is not · is one of · is not blank.
  • Number rules: "Treat values within [1] of the limit as Needs review". 0 turns it off.
  • Add, remove, reorder (move up / down) by keyboard.
  • Column types shown: number / text / mixed (highlighted).
States and errors6
  • Several sheets: picker, first selected; switching clears rules on missing columns, with a note.
  • Renamed columns: notice listing each rename.
  • No rules: Check students disabled: "Add at least one rule."
  • Incomplete rule: field marked and named.
  • Mostly non-numeric column: Most values in Attendance are not numbers. Results for this rule will mostly be Needs review. Can continue.
  • Rule set column missing: Column 'Attendance %' is not in this file. Choose a column for this rule.
How we'll know it works3
  • At 5 rules "Add rule" is disabled; removing one re-enables it.
  • "is not blank" hides the value field.
  • Add, edit, reorder, remove with the keyboard only.

Checking Students

  • Exactly one group per row, with a reason; several issues all listed.
  • Counts must add up, or an error and no partial results.
  • Needs review first, then Not eligible, then Eligible.

Reviewing Results

  • Counters filter; search ID, name, any cell.
  • Rule impact per rule, plus duplicate checks.
  • Row panel: every cell, each rule's outcome, every reason. Esc closes.
Reason sentences9
  • Not eligible Attendance is 72, below the 75 limit.
  • Needs review Attendance is 75.4, within 1 of the 75 limit. Confirm before deciding.
  • Needs review Attendance is 'AB', not a number. Check manually.
  • Needs review Attendance is '75 %', a number stored as text. Confirm the value.
  • Needs review Attendance is '74,6', which uses a comma. Check whether it means 74.6.
  • Needs review Attendance is blank.
  • Needs review Roll number S017 appears twice (rows 18 and 203).
  • Needs review Possible duplicate: 'S. Kumar' and 'SURESH KUMAR' share date of birth 2004-03-11.
  • Eligible Meets all 2 rules.
Saving and Sharing Results3
  • .xlsx: "Results" (original columns + Status + Reason) · "Rules used" (rules, margin, timestamp, file, sheet, counts) · "Needs review".
  • Rule set .json: rules and margins only, no student data. Missing columns can be remapped on load.
  • Print: file name, date, rules, counts, table. No buttons.
How we'll know it works9
  • Sample data + demo rules: "120 of 120 students checked", counters add to 120.
  • Every inserted trap lands in Needs review with its reason.
  • Raw values match the file ("9.6", "AB", "10 ").
  • "Needs review" filter count matches the counter.
  • Row panel shows every original column.
  • Rule impact matches a manual count of the sample.
  • .xlsx opens in Excel with 3 sheets, values unchanged.
  • Saved rule set reloads and reproduces the same counts.
  • Print preview: rules, counts, table, no buttons.

04

Product Decisions

Learner decisions9
  • Three groups, not pass/fail: uncertain cases go to a human.
  • Flag only, never fix or merge: the office owns the data.
  • Raw values always shown: rounding is how 74.6 becomes 75%.
  • AND-only, max 5 rules.
  • Margin default 1, editable.
  • Count invariant with hard error.
  • Everything stays in the browser.
  • Rule sets as .json files, no accounts.
  • Name: Rollcheck (agent-chosen at the learner's request).
Confirmed at review3
  • equals / is not / is one of: case-insensitive, outer spaces ignored; number columns compare numbers ("75" = "75.0"); no margin. Raw value always displayed.
  • Mostly-non-numeric warning above 50% of non-blank cells.
  • Both rows of a duplicate pair flagged; each reason names the other row number.
05

Boundary

Deferred implied but not built4
  • In-app rule-set library: .json files cover reuse.
  • Merging two files: separate matching problem.
  • OR-logic: builder and reasons get much harder to read.
  • Remembering last file or rules: would store student data in the browser.
Non-goals5
  • No AI inside the app.
  • No login, server or database.
  • No scheduling.
  • No editing data.
  • No mobile-first design.
