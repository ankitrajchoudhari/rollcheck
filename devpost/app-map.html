The app in one paragraph

Rollcheck is a single web page. Office staff upload a student sheet, set up to five rules, and every student is sorted into Eligible, Not eligible or Needs review with a reason. A pure, tested engine (src/engine/) makes every decision; a background worker (src/worker/) runs it so big files don't freeze the page; the screens (src/ui/) only display results. Nothing is stored or sent anywhere — only the theme choice is remembered.

One action, end to end: clicking “Check students”

Text version: App.tsx → worker client → engine (evaluate, review, decide, invariant) → Results screen.

A three-stop route (reference — not toured live)

Open these in your editor; search for the anchor in quotes.

  1. Every cell is classified, never guessed. src/engine/classify.ts · search "export function classifyCell". Decides whether a cell is a clean number, a number stored as text ("10 ", "75 %"), a comma decimal ("74,6"), text ("AB") or blank — and keeps the raw text beside it.
  2. Each rule meets each cell. src/engine/evaluate.ts · search "function evaluateNumber". The strict near-limit margin (Math.abs(v - limit) < rule.margin) and every reason sentence (from src/engine/reasons.ts).
  3. The row is decided and the counts are proven. src/engine/group.ts · "export function decideStatus" (any fail → Not eligible; any flag → Needs review), then src/engine/invariant.ts · "export function assertInvariant", which withholds the result unless every row is in exactly one group.

A practice to reuse

Put the decisions in a small, UI-free core and test it against the cases you are afraid of — before any screen exists.

In this build the first slice was the engine alone, with tests written from the PRD's edge cases. One of those tests — src/engine/read.test.ts, “shows the real stored value, not the rounded display” — failed on the first run: Excel's plain 0 number format was being treated as ID padding, so 74.6 would have been shown as 75, the exact silent rounding the product exists to prevent. The fix was one character in src/engine/parse.ts (/^00+$/), found before any UI was built.

The second case was found the other way round: an Excel-re-saved CSV arrived as one column during hands-on testing. It became a regression test first (“splits a semicolon CSV that Excel squeezed into one column”), then a fix in src/engine/read.ts · splitSingleColumn.

On another project: write the scary inputs as tests against the core first; when a real user finds a new one, turn it into a test before fixing it.
