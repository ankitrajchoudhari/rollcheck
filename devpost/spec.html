Decided at review

1 · Is a value exactly at the edge "within" the margin?

Rule G3 is at least 10, margin 1. In the first 120 real sample rows, 17 students have G3 exactly 10 and 5 have absences exactly 10. Any positive margin puts values equal to the limit in review.

Strict |v − L| < m
99.61010.411

~22 near-limit rows + ~8 traps in review.

Inclusive |v − L| ≤ m
99.61010.411

~45+ rows in review.

Decided: strict. Checked in the build by the margin-boundary unit test and the real demo counts.

2 · Percent-formatted .xlsx numbers

Excel stores a cell shown as "75%" as 0.75. Should "attendance is at least 75" compare against 75 or 0.75?

Decided: compare as the percent (0.746 → 74.6), display 74.6%, and note in the row detail that Excel stores 0.746. That reads the cell's own format; it isn't a guess.

01

How This Works, In Plain Language

Rollcheck is one web page that runs entirely in the browser. Once it has loaded, the student file is read and checked on this computer and never sent anywhere.

1 · Engine

Plain TypeScript, no UI. Decides each group and writes the reasons. Fully unit-tested on its own: your practice goal.

2 · Worker

A second browser thread. Big files are read and checked there, so the page never freezes.

3 · Screens

React components that only display results and pass on choices. No eligibility logic.

7numberFailG3 is 7, below the 10 limit.

ABtextReviewG3 is 'AB', not a number. Check manually.
12%text-numberReview…'12%', a number stored as text. Confirm the value.

Row precedence: any Fail → Not eligible · else any Review or duplicate flag → Needs review · else Eligible. All reasons are listed.

09

Failure Modes and Simplifications

Where it could break4
  • Huge .xlsx → read in the worker with "Reading file…"; Start over terminates the worker.
  • Odd formats (dates, #N/A, percent) → raw text kept; not a clean number → Needs review.
  • Engine bug → invariant error, no partial results.
  • No Worker → same engine in-thread; slower, still correct.
Simplified, on purpose4
  • Rule sets as .json downloads, not an in-app library.
  • Coarse .xlsx read progress (SheetJS reads in one call).
  • Rule-based duplicate names, not fuzzy matching: explainable in one sentence.
  • Sample as CSV; .xlsx covered by test fixtures.
