# Data sources

Rollcheck contains **no real student data**. The only data in this repository is a public research dataset and a demo sheet built from it with clearly marked, deliberately inserted problems ("traps").

## The demo sheet: `public/sample/rollcheck-sample.csv`

This is what **Try sample data** loads. It is generated by [`scripts/make-sample.mjs`](scripts/make-sample.mjs) (`npm run sample`), deterministically, from the file above. A machine-readable list of the traps is written to [`data/sample-traps.json`](data/sample-traps.json), and [`src/sample.test.ts`](src/sample.test.ts) checks that every trap lands in **Needs review** with the expected reason.

### Changes made to the original data (as required by CC BY 4.0)

1. Kept the **first 118 students** in file order, with all 33 original columns.
2. Added a **`Student ID`** column (`S001` … `S118`).
3. Added a **`Student Name`** column with **synthetic names** made by combining common Portuguese first names (chosen by the row's `sex`) and surnames. These are not real people. The original dataset has no names.
4. Changed **six values** and inserted **two rows** to create the traps below. Every other value is exactly as in the source.
5. Wrote the result semicolon-separated, like the source. That makes **120 students** in total.

### Inserted traps

Row numbers are as a spreadsheet shows them (row 1 is the header). Demo rules: **absences is at most 10** AND **G3 is at least 10**, margin 1, duplicates matched on **age** and **school**.

| Row | Student ID | Column | Original | Changed to | What it tests | Expected reason (Needs review) |
|---|---|---|---|---|---|---|
| 13 | S012 | G3 | `12` | `9.6` | A decimal value just under the limit, which a rounded display would show as 10 | G3 is 9.6, within 1 of the 10 limit. Confirm before deciding. |
| 22 | S021 | absences | `0` | `AB` | "AB" (absent) instead of a number | absences is 'AB', not a number. Check manually. |
| 32 | S031 | absences | `0` | *(blank)* | A blank cell in a rule column | absences is blank. |
| 44 | S043 | absences | `2` | `10 ` (trailing space) | A number stored as text | absences is '10 ', a number stored as text. Confirm the value. |
| 52 | S051 | G3 | `13` | `12%` | A "75%"-style percentage stored as text | G3 is '12%', a number stored as text. Confirm the value. |
| 67 | S066 | G3 | `15` | `9,8` | A comma used as the decimal mark (never guessed) | G3 is '9,8', which uses a comma. Check whether it means 9.8. |
| 72 | S071 | Student Name | — | `Pedro Ribeiro` | The original of a student entered twice | Possible duplicate of row 120: 'Pedro Ribeiro' and 'P. RIBEIRO' share age … and school … |
| 120 | S119 | *(inserted row)* | — | copy of S071, name `P. RIBEIRO`, new ID | The same student entered again with a different spelling, same age and school | Possible duplicate of row 72 … |
| 82 | S081 | Student ID | — | `S081` | The original holder of an ID that is used twice | Student ID S081 appears twice (rows 82 and 121). |
| 121 | S081 | *(inserted row)* | — | a different student (`Vasco Nunes`) given the ID `S081` | One ID typed for two different students | Student ID S081 appears twice (rows 82 and 121). |

Each trap was placed on a row that would otherwise be clearly eligible (absences ≤ 6, G3 ≥ 12), so the trap's reason is the only reason on that row. The duplicate rows are **flagged, never merged**.

With the demo rules the sample gives **120 of 120 students checked: 56 Eligible, 35 Not eligible, 29 Needs review**. Of the 29, the ten trap rows above are deliberate; the rest are real values exactly at a limit (for example G3 = 10, or absences = 10), which the near-limit margin sends to review.
